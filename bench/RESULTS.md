## Workloads

- **py_parity**: the Python engine's own benchmark op stream, recorded by `bench/py_parity/export_trace.py` running `demo.trader` unchanged (seeds 42, 43, 44, single-threaded) against the Python engine at commit a7e19ca. 13,811 ops = 12,000 submits (90% limit over a 101-tick band, 10% market, qty 1..100) + 1,811 cancels. `bench/py_parity/py_parity.bin`, sha256 `8f7bc6e745150071...`. One run = 200 back-to-back replays, each on a fresh book (throughput) or 20 (latency).
- **shape**: the same distributions generated in C++ (`bench/workloads.hpp`), 1,000,000 submits, seed 1. One replay per run.

Every book's end state on py_parity (trades, traded qty, resting orders, every price level's qty) matched the Python engine's recorded end state, and all books matched each other on shape. The script refuses to write this file otherwise.

## What this does not measure

- One thread, one instrument, in-process calls: no network, no parsing, no queueing.
- Throughput numbers are single-threaded matching speed. No thread count produced them.
- macOS cannot hard-pin a thread to a core; the QoS hint above is all that was applied.
