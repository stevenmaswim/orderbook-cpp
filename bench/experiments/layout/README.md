# Upgrade F: layout experiments

Each `.patch` here is one layout idea, applied on top of the commit named in
`RESULTS.md` (`head`). `RESULTS.md` is generated by
`bench/experiments/ab_variants.py` and holds every number; this note only
records the decisions.

| Variant | Idea | Decision |
|---|---|---|
| `head` | `Level` is 32 bytes (unused order count removed) | **Kept.** Faster than the 40-byte level for `pool_array` on all three workloads in every run, most clearly on `wide`, where the best-level scan walks many levels. |
| `level40_with_count` | the previous 40-byte `Level` | Reverted (this is the "before" of the change kept above). |
| `order_align64` | `alignas(64)` on `Order` so no node crosses a 64-byte boundary | **Rejected.** No consistent direction across workloads and runs. |
| `order_no_price` | drop `Order::price` (the level already knows it), 56-byte `Order` | **Rejected.** Faster on some workloads, slower on others; not a consistent win, and it adds a pointer hop to read a maker's price. |

Hot/cold split: every field of `Order` is read or written when the order is
matched or cancelled, so there is no cold field to move out. `seq` is the only
candidate (only snapshots read it), but moving it to a side array would add a
second cache line to every rest, so it was not tried.

False sharing: the book is single-threaded by design, so its structures have
no cross-thread sharing. The check that matters is on the SPSC ring between
threads (upgrade E), where the producer and consumer indices are padded onto
separate 128-byte lines and measured both ways.

The machine had background load during these runs (load average recorded in
`RESULTS.md`); the min .. max columns show how much that moved individual
rounds. Rerun on an idle machine before quoting any figure.
